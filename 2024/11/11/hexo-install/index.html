4.Github注册与创建仓库

  3. 注册完成后，点击右上角的+按钮，选择New repository，创建一个<用户名>.github.io的仓库。

  • 仓库的格式必须为：<用户名>.github.io (注意：前缀必须为用户名，不要等后面404了再来为什么！！！)

  • 勾选 Initialize this repository with a README 初始化一个 README.md 文件
  • 点击 Creat repository 进行创建

文件：[Blogroot]/scaffolds/post.md ｜ 改法：替换文件内容，首尾要补上 --- 分隔线；以后 hexo new "文章标题" 生成的新文章就是这套字段。

改完怎么验证与部署

安装、换主题、改配置这几步做完，先在本地走一遍再上传。下面命令都在博客根目录（[Blogroot]）执行。

  1. 生成：hexo generate（简写 hexo g）。看输出最后是不是 Generated，出现报错先解决再往下走；动过 _config.yml 或主题后重新生成一次。
  2. 本地预览：hexo server（简写 hexo s），浏览器打开 http://localhost:4000。首页、任意一篇文章、分类页各点一遍，确认主题样式、文章列表和侧栏都正常。
  3. 清缓存 / 强制刷新：改过 source/ 下的 CSS、JS 或 _config.butterfly.yml 之后按 Ctrl + F5 硬刷新；如果浏览器还是老的，重启 hexo server 再刷新。
  4. F12 查 404：打开开发者工具，Console 看有没有红色报错，Network 里按状态码筛 404。常见原因是静态资源路径写错（/css/、/js/ 开头有没有漏）、inject 里引用的文件没放进 source/、主题的 _config.yml 没改名成 _config.butterfly.yml。
  5. 部署：按你原来的托管方式把生成的 public/ 传上去——Nginx / 云服务器直接把 public/ 内容覆盖到站点根目录；GitHub Pages 用 hexo deploy（先按第 8 节配好 deploy 再执行 hexo deploy）；Vercel 等平台连仓库，构建命令填 hexo generate、输出目录填 public。上传后关掉浏览器缓存再访问一次，确认线上和本地一致。

上线前再确认三件事：_config.yml 和 _config.butterfly.yml 的缩进没被编辑器改成 Tab（YAML 只认空格）；新增的 scripts/*.js 放在博客根目录的 scripts 里而不是主题目录里；deploy 里的仓库地址和分支跟你的托管方式对得上。
