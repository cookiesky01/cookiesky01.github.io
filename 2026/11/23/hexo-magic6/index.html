本篇从第 61 个魔改开始，先写列表页文章少时，公告、欢迎来访、倒计时和那年今日自动下移到文章下方、整页全宽展开；后续 62 起继续补在这一篇。适用 Hexo 8.1.2 + Butterfly 5.7.2。

阅读约定：每个代码块上方都标了 文件 与 改法。[Blogroot] 指博客根目录；「新建」是建好文件后整段写入，「追加」是放到文件末尾，「在已有文件的某函数内补全」是在已有脚本里改对应位置，不要另建一份。

这一节改哪里
  • 61：列表页文章不足时，侧栏内容卡下移全宽展开，文章变多后逐张收回

需要的基础：第 52 节已经做过「欢迎来访」「倒计时」，第 53 节已经做过网站信息卡下移。这两节没有做的话，脚本仍能运行，但只会搬动页面上实际存在的卡片。

61. 列表页文章少时，网站信息与侧栏卡下移全宽展开

效果

分类页、标签页或最后一页文章很少时，主列表只有两三张卡片，右侧却还挂着一整列侧栏，页面下半截会出现一块很大的空白。原来的第 53 节只把「网站信息」搬到主列底部，主列仍然只占 74% 宽，右边那一截还是空的。

这一节把「网站信息」也从主列请出来，和公告、欢迎来访、倒计时、那年今日一起排进 #content-inner 的整页全宽网格：

  • 桌面端（≥ 900px）先量主列表和侧栏的真实内容高度。
  • 网站信息放第一行，公告第二行，欢迎来访占 7/12、倒计时占 5/12，那年今日收尾；页面上缺哪张就跳过哪张。
  • 每搬一张重新量一次，侧栏高度回到主列表附近就停，不会一次全部搬空。
  • 新增文章把空间占掉后，下一次同步会先全部放回原位，再按新的剩余空间重新分配，所以只收回不需要的那几张。
  • 手机端不搬，网站信息和侧栏卡全部放回，保持整页纵向滚动。

本站 1440px 下实测：第 4 页（3 篇）展开网站信息、公告、欢迎与倒计时；4 ~ 6 篇只展开网站信息、欢迎与倒计时；8 篇只展开网站信息与欢迎；10 篇以上不再展开。这个数量不是写死的，由高度计算得出。

为什么不能直接 appendChild 了事

只在需要的时候移动卡片，必须解决三件事：

  1. 原位怎么记：卡片原来在 #aside-content 里，有的在 .sticky_layout 里，有的直接挂在侧栏下。只记父节点不够，还要记它在兄弟节点中的位置，否则恢复后顺序会乱。
  2. 高度怎么量：主列表和侧栏都是 flex 子项，侧栏会被拉伸到和主列表一样高。直接读 aside.offsetHeight 永远量不出「侧栏内容其实更矮」，要取它直接子元素的最底部。
  3. pjax 怎么活：pjax 只替换 #body-wrap，脚本本身还在。必须监听 pjax 完成事件重新同步，同时避免重复创建容器。
  4. 网站信息不在侧栏：第 53 节先把 .card-webinfo 搬进了 #recent-posts，它的位置由 list-webinfo.js 管。展开脚本要先找到这张卡，再和侧栏卡一起处理；只查 #aside-content 是找不到的。

本站的做法是：搬走之前在原位插一个注释节点 <!--hg-side-fill-slot--> 当占位，回来时插到注释前面，再把注释删掉。网站信息和侧栏卡都按这个办法记位置，注释不可见、不占布局，顺序却可以精确保留。

第一步：新建同步脚本

文件：[Blogroot]/source/js/list-side-fill.js ｜ 改法：新建文件，整段写入。

几个关键点：

  • CARD_SELECTORS 的第一项是 .hg-webinfo-inline，保证网站信息一定跟着展开；顺序只是搬运顺序，最终视觉顺序由 CSS 的 order 决定。
  • findCard() 先在侧栏找，找不到网站信息时再查整个文档；网站信息在主列里，只查侧栏会漏掉。
  • GAP_MIN = 220 是「侧栏比主列表高出多少才值得搬」的阈值。差得太少时不折腾，避免页面在临界点反复切换。
  • contentHeight() 只看直接子元素的最底部，不读元素自身高度，绕开 flex 拉伸造成的假高度。
  • run() 每次先 restore() 再重新判断，保证无论上次搬到哪一步，这一轮都从完整布局开始算，不会越搬越偏。
  • restore() 把网站信息放回主列、侧栏卡放回原处，然后同时清理主列和侧栏里的旧占位注释。
  • moveToHost() 会去掉 wow，并把 visibility 和 animationName 写成内联值。不处理的话，卡片在首屏之外会一直停在入场动画的透明状态。
  • 最后给容器加上 hg-fill-has-welcome / hg-fill-has-countdown，CSS 靠这两个类决定欢迎卡和倒计时是并排还是单独铺满。
  • 每次搬完派发一次 resize，让目录、距离估算等依赖尺寸的模块重新计算。

DOM 里看到 <!--hg-side-fill-slot--> 是正常的，它正在替卡片占着原来的位置；卡片全部放回后脚本会清掉这些注释。

第三步：全宽容器与美化

文件：[Blogroot]/source/css/custom.css ｜ 改法：追加到文件末尾。

布局逻辑：

  • #content-inner.hg-side-fill-on 打开 flex-wrap，让下面的全宽容器能换到新一行。
  • #hg-side-fill 占满整行，内部是 12 列网格：网站信息、公告、那年今日各占一整行，欢迎来访占 7 列、倒计时占 5 列。
  • 屏幕宽度小于 1100px 时，欢迎和倒计时改成 6 / 6 平分，避免倒计时进度条被挤得太窄。
  • 用 order 固定视觉顺序：网站信息 → 公告 → 欢迎来访 → 倒计时 → 那年今日。DOM 的搬运顺序和视觉顺序可以不同，pjax 往返后也不会乱。
  • 容器带 hg-fill-has-countdown 时才并排；没有倒计时，欢迎卡自动铺满整行，并改成左右分栏、诗句在右，避免一整条横卡只有左边一小段字。
  • 网站信息在容器里固定 4 列（窄屏 3 列），每个统计项两侧对齐；那年今日改成横向紧凑条，标题在左、日期和事件居中，不再是一整条空卡。
  • 搬出来的卡片会丢失侧栏内边距，所以欢迎、倒计时、公告、那年今日统一补 20px 24px，网站信息补 20px 26px；不补的话标题和链接会贴边。
  • 屏幕宽度到 1200px 以上时，公告里的入口从两列变四列。

调参与边界

  • 什么时候不启用：窗口小于 900px、页面没有文章、找不到 #aside-content 或 #content-inner 时直接返回，不做任何移动。
  • 只处理列表页：主容器按 recent-posts、category、tag 依次查找，文章页和独立页面不参与。
  • 搬哪些卡：选择器顺序是 .hg-webinfo-inline、.hg-welcome-card、.hg-countdown-card、.card-announcement、.card-history。想少搬一张，从数组里删掉对应项；想改变视觉顺序，改 CSS 的 order，不要改 JS 的搬运顺序。
  • 阈值不合适：文章卡片特别高或特别矮时，把 GAP_MIN 调大，侧栏要高出更多才展开；调小则更容易展开。本站用 220。
  • 单卡不好看：只剩欢迎卡时，CSS 的 :not(.hg-fill-has-countdown) 规则会把它改成左右分栏；如果主题结构不同，把这段删掉，只保留单列也能用。

改完怎么验证

  1. 生成：在博客根目录执行 ./node_modules/.bin/hexo generate，确认最后一行是 Generated。
  2. 短列表：找文章最少的一页（本站是第 4 页，3 篇），桌面宽度下检查：
    • 文章下方出现一条横跨主栏和侧栏的展开区；
    • 网站信息第一行铺满，统计项按四列排开；
    • 公告铺满一行，欢迎来访和倒计时按 7 / 5 并排；
    • 右栏保留作者卡或那年今日，没有被搬空；
    • 标题、公告入口和倒计时与卡片边缘之间保留内边距，没有贴边；
    • 页面没有横向滚动条。
  3. 动态回收：临时复制文章卡片，分别凑到 4、6、8、12 篇，每次调用一次 window.hgSideFillSync()。数量应逐级减少，12 篇时容器消失、全部卡片回到侧栏，顺序和原来一致。
  4. 手机端：把宽度缩到 390px，确认展开容器被移除、网站信息回到侧栏、所有卡片归位，页面可以整页向下滑，不出现内部滚动条。
  5. pjax：从首页点到第 4 页，再返回首页，确认 #hg-side-fill 只有一个，没有重复容器，也没有卡片丢失。
  6. 硬刷新：改过 CSS / JS 后按 Ctrl + F5；启用了 Service Worker 的话，到 DevTools → Application → Service Workers 点一次 Update。
