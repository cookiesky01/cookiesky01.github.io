这一篇单独讲「综合美化模块」：把主题色、卡片透明度、字体、壁纸、布局和特效收进一个弹窗面板，改完即时生效，刷新后保持。适用 Hexo 8.1.2 + Butterfly 5.7.2。

借鉴：Fomalhaut（猕猴桃）。本站改动：面板结构、CSS 变量、持久化与动画降级按本站实现重写，不是原样搬运。

阅读约定：每个代码块上方都标了 文件 与 改法。[Blogroot] 指博客根目录；「新建」是建好文件后整段写入，「追加」是放到文件末尾，「在已有文件的某函数内补全」是在本站已有的同名脚本里改对应位置，不要另建一份。面板外观类样式放 source/css/beauty-panel.css，卡片底色、字号、圆角这类全局魔改放 source/css/custom.css，两者不要混。

综合美化模块到底做了什么

一般的主题换肤，要么改 _config 重新生成，要么在浏览器里用开发者工具临时改两下。综合美化模块把这两件事合在一起：

  • 入口固定：导航栏一个调色盘按钮，右键菜单里也能打开同一个面板。
  • 即时预览：拖滑块、点色点、换字体，页面立刻变化，不刷新。
  • 持久保存：偏好写进 localStorage，下次打开还是你调好的样子。
  • 互不打架：所有外观都收口到一组 CSS 变量和 <html> 上的类名，主题源码一行不用改。

它不是一个单独的插件，而是「一个首屏脚本 + 一份样式 + 一个面板脚本 + 几组特效脚本」拼起来的模块。下面按这个顺序讲，每一步都写明改哪个文件。

开始之前：文件与加载顺序

文件清单

整套模块按职责拆成这些文件，路径都在博客根目录 [Blogroot] 下：

文件职责
source/js/fomal/boot.js首屏同步脚本，读 localStorage 并写 CSS 变量，防止刷新闪烁
source/js/fomal/winbox.min.js弹窗组件 WinBox，提供可拖动、可最小化的面板外壳
source/js/fomal/notify.js轻提示，面板操作后的「已切换」小弹窗
source/js/fomal/fonts.js字体选择、字体加载检测
source/js/fomal/backgrounds.js壁纸、纯色、自定义链接三种背景
source/js/fomal/snow.js落雪（Canvas）
source/js/fomal/fireflies.js萤火虫微光（纯 CSS 动画）
source/js/fomal/ripple.js点击涟漪
source/js/fomal/panel.js面板本体：HTML、分组、交互、恢复默认
source/css/beauty-panel.css面板皮肤 + 外观开关 + 变量落点
source/css/custom.css主题色变量、卡片底色、圆角、字体基准等全局规则

加载顺序很重要，先记住一句话：首屏脚本同步放 head，其余依赖放 bottom 且保持「底层能力 → 面板」的先后。

一、设计思路：首屏同步 + CSS 变量 + 单一数据源

三层结构

综合美化模块分成三层，各管一件事：

  1. 数据层：localStorage。所有偏好只存一份，键名统一在 boot.js 里声明。
  2. 应用层：boot.js 在 <head> 里同步执行，把偏好翻译成 CSS 变量和 <html> 类名。
  3. 交互层：panel.js 只负责面板渲染和事件，改完值后同时「立即改样式 + 写回 localStorage」。

boot.js 必须是同步脚本，不能加 defer。它要在浏览器绘制第一帧之前就把变量写好，否则会先闪一下默认蓝色、默认字体，再跳成你的配置。

键名集中管理的好处是：boot.js、panel.js、特效脚本都引用同一张表，以后改名只改一处。

然后一次性把变量写进 <html>：

面板分组

面板内容由 panelHTML() 一次性拼好，再塞进 winbox.body。目前分这几组：

  • 显示偏好：卡片不透明度、背景滤镜开关、模糊 / 饱和度 / 对比度。
  • 氛围特效：星空、霓虹、雪花、萤火虫、昼夜过场档位。
  • 互动挂件：猫咪、听话鼠标、帧率监测、点击涟漪、性能模式。
  • 布局与部件：右侧部件、顶栏常驻、侧栏显示、右侧图标颜色、侧栏位置。
  • 主题色：11 个预设色点 + 自定义取色器。
  • 字体：正文 / 代码字体、整站字号、卡片圆角。
  • 背景：壁纸、纯色、自定义 HTTPS 链接。

六、背景设置：壁纸、纯色、自定义链接

文件：[Blogroot]/source/css/beauty-panel.css ｜ 改法：追加到文件末尾的背景图规则区。

「自定义」页签只接受 https:// 开头的图片链接，取色器也只接受十六进制颜色。校验放在应用前，而不是等 CSS 渲染失败：

文件：[Blogroot]/source/js/fomal/boot.js ｜ 改法：在已有文件的 bgToCss() 函数内补全，并确认已导出到 HGBeauty.bgToCss；backgrounds.js 里只调用，不重复实现。

如果你同时把壁纸写进主题配置，注意 Butterfly 5.x 的 background 只填纯路径或颜色，例如 background: /img/bg.webp。5.x 会自动包一层 url()，你再手写 url(...) 就会变成双层 url()，最终背景 404、首页空白。综合美化模块内部存的是 url(...)，所以它自己负责用 bgToCss() 转换，两套逻辑不要混用。

八、特效开关：默认值、互斥与降级

雪花

雪花用 Canvas 绘制，核心是「预渲染雪片 + 时间驱动 + 有限高度积雪」：

  • 雪片不是每帧重新画路径，而是预先渲染两种尺寸的六臂雪片贴图，帧里只做 drawImage。
  • 位置按时间差推进，切后台再回来不会瞬移。
  • 落地后在底部累积一层薄雪，并给新雪片留出空间。
  • 只在浅色、桌面端（宽度 > 768px）且系统没有要求减少动态效果时运行。
  • 页面隐藏、pagehide、系统开启 prefers-reduced-motion 时自动停掉绘制循环。

文件：[Blogroot]/source/js/fomal/snow.js ｜ 改法：在已有文件的 frame() 函数内补全，落地积雪与重置雪片写在绘制之后。

默认开启，但只在白天桌面生效；夜间、手机和「减少动态效果」偏好下会自动隐藏，不需要用户额外操作。

萤火虫、涟漪与互斥

萤火虫是纯 CSS 动画，没有 Canvas、没有 requestAnimationFrame、没有常驻定时器：

  • 桌面 14 个、窄屏 8 个光点，随机分布在下半屏。
  • 每个光点独立设置漂移时长、呼吸时长、延迟和颜色，靠 CSS 变量驱动。
  • 页面隐藏时给容器加 hidden，动画暂停。

十、接入步骤与避坑清单

五步接入
  1. 放文件：把 boot.js、panel.js、fonts.js、backgrounds.js、snow.js、fireflies.js、ripple.js、winbox.min.js 放进 [Blogroot]\source\js\fomal\；把 beauty-panel.css 放进 [Blogroot]\source\css\。
  2. 注入资源：改 [Blogroot]\_config.butterfly.yml 的 inject，注意 boot.js 同步放 head，其余按依赖顺序放 bottom。
  3. 加入口：改 nav.pug 和 rightmenu.pug，两处都调用 toggleWinbox()。
  4. 补全局样式：在 custom.css 里补 --hg-font、--hg-radius 和卡片底色规则；主题色、目录高亮、右侧图标等写死颜色的地方按前面的方式接到变量上。
  5. 本地验证：npx hexo generate 后打开页面，逐项拖动滑块、切换字体和壁纸，再刷新确认状态保持。

配置参考（版本号和你的实际文件保持一致即可）：

文件：[Blogroot]/_config.butterfly.yml ｜ 改法：并进已有的 inject 配置，boot.js 放在 inject.head 列表里且不加 defer，其余按顺序放进 inject.bottom 列表；已有同名资源就改原行，不要重复添加。

为什么顺序不能乱：panel.js 在创建面板时要读取 HGBeauty、HG_FONTS、HG_BACKGROUNDS，还要给雪花、萤火虫、涟漪挂开关；这些都必须在它之前加载。WinBox 也必须比 panel.js 先到，否则面板创建时会提示「弹窗组件没加载成功」。

避坑清单
  • boot.js 不要加 defer：它必须在首帧前执行，否则刷新会闪默认样式。
  • Butterfly 5.x 首页多了一层 .recent-post-items：卡片透明度、双排布局等选择器都要同时匹配两层。
  • 不要全局覆盖 --btn-color：会让右侧图标和大量圆形按钮一起变深，应使用 --hg-rightside-color 这类专用变量。
  • 模糊值 0 不要放大背景：hg-bg-filtered 和 hg-bg-blurred 分开判断，只有 blur > 0 才执行 scale。
  • 系统字体直接放行：Consolas、Monaco、系统默认字体不要交给 document.fonts.load() 判断，避免误报加载失败。
  • 字号改 body，不要改 html：主题把基准字号写在 body 上，改 <html> 没有效果。
  • 主题配置里的背景只写路径：Butterfly 5.x 会自动包 url()，手写 url(...) 会变成双层。
  • 键名集中管理：boot.js、panel.js 和特效脚本共用同一张键名表，改名要一起改。
  • 最小化居中要等一帧：WinBox 先在回调里贴左下，setTimeout(..., 0) 后再按实际标题栏高度计算居中位置。
  • 改完配置文件强刷：?v= 参数用来打破缓存；如果预览没变化，重启 hexo server 再强制刷新一次。

最后提醒一句：面板的价值在于「收口」。新增任何外观项，都先问自己能不能变成一个 CSS 变量或一个 <html> 类名；能的话，面板只需要加一个控件和一次 setProperty()，不要再写一套独立逻辑。

小结

综合美化模块的核心只有三句话：首屏同步应用偏好，所有外观走 CSS 变量和类名，面板只负责交互与持久化。按这篇文章的顺序接入，你可以得到一个即时生效、刷新保持、移动端也不会挤爆的美化面板。

下一步，打开面板把主题色调成你喜欢的颜色，再切换一次正文字体——这两项最能立刻看出模块是否接对了。

延伸：列表页短内容的展开卡片

列表页文章不足时，网站信息、公告、欢迎来访、倒计时和那年今日会进入 #hg-side-fill 的整页全宽网格。这部分没有新增面板控件，颜色、圆角和卡片底色继续吃美化面板的 CSS 变量；容器上的 hg-fill-has-welcome、hg-fill-has-countdown 只负责布局分栏，不是新的持久化偏好。

卡片搬出侧栏后要把 20px 24px 内边距一起补上，否则标题会贴边；这类规则和颜色变量一样都落在 custom.css。完整测量、搬运、逐张回收和 pjax 恢复逻辑在 hexo魔改教程（六），本节不重复代码。

改完怎么验证与部署

文件放好、inject 顺序也对齐之后，不要直接上传，先按这个顺序走一遍：

  1. 生成：在博客根目录执行 hexo generate，命令行出现 Generated 再往下走。这一步报错，九成是 _config.butterfly.yml 的 inject 列表缩进或路径写错，先修配置再看别的。
  2. 本地预览：执行 hexo server，打开 http://localhost:4000。打开面板依次试主题色、卡片不透明度、正文字体、壁纸和各特效，然后刷新一次，确认 boot.js 把偏好恢复回来、首帧不闪默认蓝色（闪一下说明它被加了 defer 或没放 head）。
  3. 强刷或清缓存：改过 custom.css、beauty-panel.css 或 fomal 下的脚本后按 Ctrl + F5；_config.butterfly.yml 里对应的 ?v= 版本号也要升一次，没升就改完重启 hexo server。启用了 Service Worker 时，再到 DevTools → Application → Service Workers 点 Update 或 Unregister。
  4. F12 查 404：Console 不应出现 boot.js、panel.js、beauty-panel.css、winbox.min.js 之类 404；Network 里筛 fomal 和 beauty-panel，确认请求全部 200 且版本号是刚改的。面板弹出「弹窗组件没加载成功」，说明 winbox.min.js 没排在 panel.js 之前。
  5. 主题色联动：打开关于页，确认贡献度日历的格子和图例颜色跟着面板主题色变化；切一次暗色模式，空格子应变暗、有色格子保留。
  6. 上传 public/：生成目录就是 public/，按原来的托管方式传上去——Nginx 直接把 public/ 覆盖到站点根目录，GitHub Pages 推送到发布分支或用 GitHub Actions，Vercel 连仓库自动构建，本地脚本托管则 hexo deploy。上线后关掉缓存再访问一次，确认线上与本地一致。

如果线上和本地不一致，先怀疑缓存而不是代码：?v= 参数、Service Worker 缓存、CDN 缓存三层里任意一层没更新，看起来都像「改了没生效」。
