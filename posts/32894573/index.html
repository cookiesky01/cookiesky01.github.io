几个关键约束：

60. 订阅源 BOM 与 custom.css 截断修复

订阅源中文乱码。 Edge 和部分阅读器在响应头没有 charset 时，会把 atom.xml 当 GBK 解码，XML 声明里的 encoding="utf-8" 兜不住。解决办法是构建完成后给订阅源补 UTF-8 BOM：

文件：[Blogroot]/scripts/feed-bom.js ｜ 改法：新建文件，整段写入。

字符串和 Buffer 两种返回类型都要处理，且要判断 BOM 是否已经存在，避免重复添加。

custom.css 截断。 这次遇到一个很隐蔽的问题：文件里有一段 @-webkit-keyframes 没有闭合，浏览器解析到那里之后，把后面所有规则整段丢弃。表现是「前面几节样式正常，后面突然全失效」，很容易误判成选择器写错。修复前后的生效规则数是 202 → 601。

排查和预防：

  1. 用 DevTools → Sources 打开 custom.css，看最后一条被识别的规则停在哪一行，问题通常就在它附近。
  2. 大段注释里不要嵌套 /* */，一个多余的 */ 就会让解析器提前结束注释。
  3. 改完 CSS 用 npx stylelint 或任意 CSS 校验器过一遍括号配对。
  4. 给 custom.css 的引用加版本参数，改一次升一次；配合 Service Worker 时，sw.js 的 VERSION 也要一起升。

改完怎么验证与部署

十节都改完后，不要直接上传，先在本地走一遍：

  1. 生成：在博客根目录执行 ./node_modules/.bin/hexo generate（Windows 下也可用 hexo generate）。看最后一行是不是 Generated，有报错先解决再继续。
  2. 本地预览：执行 hexo server，打开 http://localhost:4000，重点检查首页多栏、侧栏两张卡、画廊、旧时光、公告卡和手机菜单。
  3. 硬刷新：改过 CSS / JS 后按 Ctrl + F5。如果启用了 Service Worker，再到 DevTools → Application → Service Workers 点一次 Update，否则看到的可能还是缓存里的旧文件。
  4. 检查控制台：F12 看 Console 有没有 404 或 Uncaught，Network 里确认 custom.css、本节新增的 JS 文件、sw.js 的版本参数已经更新。
  5. 部署：把生成的 public/ 目录按你原来的方式上传（Nginx 静态托管、GitHub Pages、Vercel 或 hexo deploy 都行）。上传后关掉浏览器缓存再访问一次，确认线上和本地一致。

上线前再核对三件事：

  • _config.yml 和 _config.butterfly.yml 的缩进没有错位，YAML 对空格数量很敏感。
  • 新增的 scripts/*.js 在博客根目录的 scripts 文件夹里，不是在主题目录里；这样升级主题不会丢。
  • 改过 custom.css 或任何 JS 后，_config.butterfly.yml 里的 ?v= 版本号和 sw.js 的 VERSION 是否一起改了。

这篇把第 51 ~ 60 个魔改写完了。首页多栏、侧栏卡片、画廊、旧时光、公告入口、Cookie、缓存与资源瘦身都已经落地。第 61 个魔改已经接着写：hexo魔改教程（六）：侧栏内容卡全宽展开。
