改完怎么验证与部署

十节都改完后，先在本地走一遍再上传：

  1. 生成：在博客根目录执行 hexo generate（简写 hexo g）。最后一行出现 Generated 才算过，有 Pug 或 YAML 报错先解决，layout.pug、rightmenu.pug 写错会直接编译失败。
  2. 本地预览：执行 hexo server（简写 hexo s），打开 http://localhost:4000，逐个确认灯笼、标题切换、星空、猫猫、鼠标样式、右键菜单、F12 拦截、帧率、控制台字符画、顶部进度条是否都生效。
  3. 强制刷新或清缓存：改过 CSS / JS 后按 Ctrl + F5；还不生效就 F12 → Application → Storage 清掉 Cache Storage。启用了 Service Worker 时先在 Application → Service Workers 里 Unregister 或勾 Update on reload，否则看到的一直是缓存里的旧文件。
  4. F12 查 404：Console 看有没有 Uncaught，Network 按状态码排序，确认 /js/denglong.js、/css/universe.css、/css/progress_bar.css 这些新路径返回 200。404 多半是目录写错（source/js 和 source/css 别混）或文件名大小写不一致。
  5. 部署：把生成的 public/ 按原来的方式传上去——Nginx 把站点根目录指向 public/、GitHub Pages 推 public/、Vercel 重新部署，或执行 hexo deploy。上传后关掉缓存再访问线上地址，确认和本地一致。

版本号别忘了同步：_config.butterfly.yml 里 /css/custom.css?v=...、/js/xxx.js?v=... 的 ?v= 改一次升一次，否则浏览器或 CDN 会继续用旧缓存，出现「明明改了却没生效」。
