改完怎么验证与部署

十节改完先别急着上传，本地按顺序走一遍：

  1. 生成：在博客根目录执行 hexo generate（或 hexo g）。最后一行出现 Generated 且没有 Pug / Stylus 报错才算过；改过主题模板后报错，多半是缩进或 include 路径写错。
  2. 本地预览：执行 hexo server（或 hexo s），打开 http://localhost:4000，逐项点到：昼夜切换按钮、美化设置按钮、导航栏宽度、文章页波浪、加载动画、打赏投币、右下角按钮、/music/、随便敲一个不存在的地址看 404、节日弹窗。
  3. 强制刷新或清缓存：改过 CSS / JS 后按 Ctrl + F5；装了 Service Worker 的再加一步，DevTools → Application → Service Workers 勾 Update on reload 或点 Unregister 后刷新，否则看到的还是旧文件。
  4. F12 查 404：Console 里不该有 Uncaught；Network 里 sun_moon.js、meihua.js、nav-fit.js、coin.js、day.js 应是 200。变成 404 基本就是注入路径和文件位置对不上——/js/xxx.js 对应 source/js/xxx.js，/css/xxx.css 对应 source/css/xxx.css。
  5. 上传 public/：按原来的托管方式发布：Nginx 把 public/ 同步到站点根目录，GitHub Pages 推 public/ 或走 Actions，Vercel 连仓库自动构建，用 hexo deploy 的再跑一次 hexo deploy。上线后换无痕窗口再验一遍，确认线上和本地一致。

还有一条要记住：themes/butterfly/ 里的改动不会跟着主题升级保留，升级前先把自己改过的模板文件备份出来。
