APlayer 左下角播放器美化

发表于2026-11-23|更新于2026-11-24|hexo
|总字数:3925|阅读时长:20 分钟|浏览量:

这篇记录左下角 APlayer 的美化过程：从默认的白色小方块，改成玻璃卡片 + 自动收起 + 暗色适配。播放器是 APlayer 内核加一个自己写的 nav-music.js 搭起来的，美化只动 CSS；照着「放内核 → 放脚本 → 挂载 → 放皮肤」的顺序做，就能复现同样的效果。

  • 仓库地址：https://github.com/cookiesky01/aplayer-fixed-skin

先看清楚结构

左边这个播放器不是 hexo-tag-aplayer 注入的，而是站里自己用脚本建的，一共三部分：

  • APlayer 1.10.1 内核：本地的 /js/APlayer.min.js 和 /css/APlayer.min.css；
  • nav-music.js：拉歌单、用 new APlayer({ container: '#nav-music', fixed: true, mini: true, ... }) 建播放器；
  • aplayer-fixed.css：本文的皮肤，只改样式。

歌单来自 api.i-meto.com/meting/api（网易云歌单 2331639478），音频走网易云外链 music.163.com/song/media/outer/url?id=歌曲ID.mp3——比 Meting 返回的直链稳，不会两三秒就 404 跳过。

渲染出来的 DOM 是这样：#nav-music 自己被加上 aplayer aplayer-fixed aplayer-narrow 这些类，卡片是里面的 .aplayer-body。暂停时 APlayer 自己加 .aplayer-narrow，所以「收起成封面」不用写 JS，CSS 接住这个类就行。

开始之前：准备文件

整个美化涉及 5 个文件，都不改主题源码：

文件 作用
[Blogroot]/source/js/APlayer.min.js APlayer 1.10.1 内核（本地化，也可以换 CDN）
[Blogroot]/source/css/APlayer.min.css APlayer 默认样式
[Blogroot]/source/js/nav-music.js 新建：拉歌单 + 建播放器
[Blogroot]/source/css/aplayer-fixed.css 新建：本文的皮肤
[Blogroot]/_config.butterfly.yml 注入 div、CSS 和两个脚本

第一步：nav-music.js

文件：[Blogroot]/source/js/nav-music.js ｜ 改法：新建，整段写入。

展开查看 nav-music.js

几个可以按自己情况改的地方：

  • PLAYLIST_ID：换成自己的网易云歌单 ID；
  • APIS：目前只留了 api.i-meto.com，换接口时保证返回 [{ title, author, songid/pic }] 这种结构；
  • 歌单结果缓存在 localStorage 里 6 小时，接口挂了会先用缓存；
  • 音频默认用网易云外链，失败时才回退到接口给的直链。

第二步：挂到页面上

文件：[Blogroot]/_config.butterfly.yml ｜ 改法：在 inject 里加入容器、样式和脚本，顺序别乱。

#nav-music 是播放器容器，no-destroy 是为了 pjax 跳转时不删它；APlayer.min.js 必须先于 nav-music.js 加载，脚本里用 defer 时要保持这个先后顺序。

一、定位：从右下角挪到左下角

APlayer 的 fixed 模式默认贴着右下角，阴影也加在外层容器上。这里把位置统一改成 left: 18px; bottom: 18px，外层透明、去阴影，阴影只留在卡片上，视觉上才像「浮」着的一张卡。

二、收起与展开：宽度必须分两段写

这是最容易踩的坑：把 left/right 改掉之后，APlayer 原来那套「展开时靠 right: 0 撑开」的规则失效，卡片会缩成封面的宽度。解决办法是给两个状态各自定宽：

以后想改宽，三处要一起改：收起、展开、手机端媒体查询，否则切换状态会跳一下。

三、玻璃卡：背景、描边、模糊与阴影

卡片本体用半透明白 + 背景模糊，边框留一圈高光，阴影用偏蓝的深色，显得干净一点：

四、封面与播放按钮

封面自己带一层渐变遮罩，压住原图的杂色；播放按钮做成渐变圆钮，悬停放大：

五、歌名、进度条与图标

歌名太长会把卡片撑开，所以标题和歌手都要省略号，标题再限个最大宽度：

进度条加粗到 3px，已播放部分直接用主题色做渐变，这样美化面板换主题色时它也跟着变：

六、歌单列表

列表也做成浮起来的玻璃面板，当前播放项用主题色浅底，滚动条单独美化：

七、暗色模式

暗色只覆盖颜色，不动尺寸和布局：卡片背景换成深色玻璃，文字、图标、列表底色各自调亮一档。

代码放在哪

美化的核心是两份文件：source/css/aplayer-fixed.css（文末折叠里的完整样式）和 source/js/nav-music.js（第一步那份脚本），按上面的 inject 引进来即可。

三个容易漏的点：

  • 改完 CSS / JS 要把 inject 里的 ?v= 版本号升一次（本站是 ?v=20261121zf 这种格式），否则浏览器和 Service Worker 会继续用旧文件；
  • 开了 Service Worker 的话，sw.js 里的 VERSION 也要一起升；
  • 皮肤不一定要单独建文件，直接粘进 custom.css 也能用，只要保证在 APlayer 默认样式之后加载。

改完怎么验证

  1. 加载：首次打开页面，控制台没有跨域报错，播放器列表里能看到歌单曲目（本站歌单 188 首）。
  2. 收起：暂停状态左下角只剩一个 66px 的方形封面。
  3. 展开：鼠标移上去，卡片展开到 402px，有上浮和阴影变化。
  4. 换主题色：美化面板里改主题色，进度条、图标悬停色、列表高亮一起变。
  5. 暗色：切到夜间模式，卡片变深色玻璃，文字仍然清楚。
  6. 手机：390px 宽度下贴边 12px，展开占满屏宽，页面没有横向滚动。

附：aplayerInject 写法的参数

如果看的是 hexo-tag-aplayer 的标记写法：

参数 说明 常用值
id 容器 ID，别和页面里别的元素重名 aplayer-oSEOhviA
class 固定类名，插件靠它识别标记，不要改 aplayer aplayer-tag-marker meting-tag-marker
data-id 歌单 / 歌曲 ID 4895239160
data-server 平台：netease 网易云、tencent QQ 音乐、kugou 酷狗、baidu 百度 netease
data-type 资源类型：playlist 歌单、song 单曲、album 专辑、artist 歌手 playlist
data-mode 播放模式：random 随机、order 顺序、single 单曲循环、circulation 列表循环 random
data-autoplay 自动播放，浏览器一般会拦截 false
data-listmaxheight 播放列表最大高度 340px
data-preload 预加载：none / metadata / auto auto
data-theme 进度条与高亮色 #e3f2f5
data-volume 初始音量，0–1 0.4
mutex 多个播放器互斥，同时只响一个 true

除了网易云还能选别的平台：把 data-server 改成 tencent（QQ 音乐）、kugou（酷狗）、baidu（百度）即可，data-id 也要换成对应平台的歌单 / 歌曲 ID。要注意两点：

  1. 能不能拉到数据取决于所用的 Meting 接口。本站实测 api.i-meto.com 对 tencent 返回空数组，网易云和酷狗正常；想用 QQ 音乐得换支持它的接口，或者自己搭一个 Meting API。
  2. 本站左下角播放器最终没走这套标记，而是用前面的 nav-music.js 直接建 APlayer——原因就是外链和接口稳定性更好控制。上面这张表供参考，如果你用 aplayerInject 才需要。
