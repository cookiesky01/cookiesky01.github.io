hexo如何直接上传服务器

发表于2026-11-23|更新于2026-11-24|hexo
|总字数:1574|阅读时长:7 分钟|浏览量:

hexo-deployer-git 的思路是推到仓库，再由托管平台发布；自己有机器和 Nginx 的话，其实可以跳过仓库这一步，hexo d 直接把 public/ 打包传上去。这篇记录本站的 scp 部署器：完整代码、配置写法、宝塔环境的几个坑。

为什么要换成 scp

  • 路径最短：本地 hexo g 出 public/，打包 → 上传 → 服务器解压，三步到位，不用等平台构建。
  • 不再依赖仓库：没有远端仓库权限问题，也不用管 Pages 的构建缓存。
  • 可以双发：deploy 写成数组，先同步 GitHub Pages 备份，再发自己的服务器，两边互不影响。

前提条件

  1. 服务器已经装好 Nginx，知道站点根目录（宝塔面板里一般形如 /www/wwwroot/你的域名）。

  2. SSH 免密：本机公钥已经加到服务器的 ~/.ssh/authorized_keys，否则每次部署都要输密码。

  3. 本机有 tar、scp、ssh：Linux / macOS 自带，Windows 用 Git Bash 也有。

第一步：写部署器

Hexo 的部署器就是注册一个名叫 scp 的 deployer：收到配置后自己决定怎么发布。

文件：[Blogroot]/scripts/deployer-scp.js ｜ 改法：新建，整段写入。

代码里几个关键点：

  • 打包：tar -czf 把 public/ 压成一个临时包，比逐个文件 scp 快得多。
  • 上传：scp -P 端口 把包丢到服务器的 /tmp，不占站点目录。
  • 解包：ssh 进服务器执行一段脚本：建目录 → （可选）清空 → 解包 → 修权限 → 删临时包。
  • 跳过 .user.ini / .htaccess / .well-known：宝塔会给站点根目录放 .user.ini 并 chattr +i，删不掉也改不了权限，硬删会报 Operation not permitted；.well-known 是证书验证用的，也不能动。
  • clean: true 只清远端目录的第一层，api/ 这类服务器自己生成的目录记得像注释里那样排除。
  • 本地临时包在 finally 里删掉，失败也不会留垃圾。

常见问题

现象 原因 处理
Permission denied (publickey) 公钥没加到服务器 重新把 id_ed25519.pub 追加到 authorized_keys，权限 600
tar: command not found Windows 的 cmd/PowerShell 没有 tar 用 Git Bash 执行，或装上 tar
部署成功但网站 404 / 403 path 不是站点根目录 对照宝塔面板「网站目录」再改
Operation not permitted .user.ini 被 chattr +i 代码已跳过它，别手动 chmod -R 全目录
首次连接提示 host key verification failed known_hosts 没有记录 先手动 ssh user@host 输一次 yes
页面样式没变 浏览器 / Service Worker 缓存 强刷，或到 DevTools 里更新 Service Worker

改完怎么验证

  1. 终端最后出现 部署完成：http://... 已更新 ...。
  2. ssh user@host "ls -la /www/wwwroot/example.com | head"，文件时间和本地 public/ 一致。
  3. 浏览器强刷首页，确认是最新内容。
  4. 改一行文字重新 hexo d -g，线上能在十几秒内看到变化。

小结

hexo-deployer-git 适合托管平台，scp 部署器适合自己有机器的场景：不用仓库、不用等构建，一个 hexo d 就上线。GitHub Pages 那边继续用 git 部署当备份，两条线互不干扰。
