黄昏落幕过场

效果：点右上角的月亮/太阳，整屏不是直接换色，而是走一段「黄昏落幕」——太阳从左上方往右下沉、月亮从左下方往右上爬，星星一颗颗亮起来，远山剪影与地平线余光跟着压暗；切回白天时完全反向（月亮落、太阳升、星星退场）。最后 350ms 从点击处做一个圆形揭幕，把新主题「揭」出来。

核心是一个自包含脚本：DOM、渐变、关键帧全部由 JS 现场创建，不依赖任何外部 CSS，所以换主题皮肤也不会互相打架。

说明：主题自带按钮的片段，一般不需要修改——要是昼夜切换按钮丢了，就照这段在 themes/butterfly/layout/includes/header/nav.pug（第 34 行附近）恢复。

三个坑，踩过就记住：

  • 主题自带的 sun_moon.js 会定义同名的全局 switchNightMode，两份一起跑就是「动画播一半被另一份掐断」。脚本里用 Object.defineProperty(window, 'switchNightMode', ...) 占住这个全局名，并且加载后 400ms / 1500ms 再赋一次值，防止被异步脚本后覆盖。
  • 连点：动画中再点不再被静默丢弃，记一个 pending，本轮收尾后自动补播一次；每次运行带 runGen 代次，旧一轮的定时器 / rAF 一律作废，不会出现「上一轮把这一轮掐了」。
  • 遮罩闪烁：mask 从 circle 0 直接跳到 160vmax 再叠一层 opacity:0，第一帧会整块消失。改成 requestAnimationFrame 逐帧写半径，overlay 全程 opacity:1，结束后才 visibility:hidden。

档位（localStorage.darkTransition）：off 直接切换／light 800ms 简化／standard 1500ms 默认／flourish 多一颗流星。系统开了「减少动态效果」时保留过场但压到 45% 时长，不做成直接消失。

5. 还有一个 hexo 的坑

改了 public/ 下的文件（哪怕只是临时 sed 调试），它的修改时间会比 source/ 新，hexo generate 会跳过复制，于是你以为改好了、其实线上还是旧的。遇到「源码明明改了但页面没变」，先删掉对应 public/js/... 再 generate，最省事。

  2. 本地预览。hexo server（默认 http://localhost:4000，端口被占就 hexo s -p 4001）。逐节点开对应页面：首页看磁贴、轮播、多栏和侧栏卡片，文章页看备案、右键菜单、猫猫绳和 FPS 药丸，评论页发一条测试评论。
  3. 强制刷新 / 清缓存。改过 source/css/、source/js/ 的话，把 _config.butterfly.yml 里 inject 对应行的 ?v=xxx 版本号改一版（如 ?v=20261111a 换成 ?v=20261111b），再 Ctrl+F5 或开无痕窗口看；还不行就删掉 public/、.deletions 和浏览器里该站点的 Service Worker 缓存后重新生成。
  4. F12 查 404。Network 面板勾上 404 过滤、刷新一次，重点看 /css/custom.css、/js/fomal/*.js、/css/brinks.css、/font/*.woff2、/webfonts/*、/img/* 有没有红条——这些基本都是路径写错或文件没放进去。再看 Console，fomalNotify、Cursor、fpsSwitch 之类报 undefined 说明脚本没注入或顺序不对（脚本要排在 jQuery 之后）。
  5. 按原托管方式上传。Nginx / 宝塔：把 public/ 整个传上去；GitHub Pages：用 _config.yml 里的 deploy: type: git 再 hexo deploy；Vercel / Netlify：把仓库推上去，构建命令 hexo generate、输出目录 public，让它自动构建。上线后再强刷一次，确认线上版本号就是刚改的那版。
